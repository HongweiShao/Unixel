## 1. 概述

### 1.1 产品定位
医学影像处理软件是一款**轻量、可本地离线运行**的桌面医学影像查看与处理工具，覆盖 DICOM / 常规图像 / NIfTI 体数据 / HTJ2K 的导入、窗位调校、格式转换与批量导出闭环。前端为 Tauri 内嵌 WebView（Vue 3 + TypeScript + Vite）。

### 1.2 设计目标
- **零学习成本**：单窗口、单主操作（"打开文件"），核心交互即"选图→调窗→导出"。
- **影像优先**：画布占据主区域，菜单/工具/状态为窄条、不挤占阅片空间。
- **实时反馈**：窗位、窗宽、缩放、帧切换均实时重绘，无确认步骤。
- **深色优先**：医学阅片以暗背景减少眩光、突出灰度影像。

### 1.3 本版界面范围
| 模块 | 文件 | 说明 |
|------|------|------|
| 应用外壳 / 布局 / 状态 | `src/App.vue` | 顶部菜单栏、主区占位、右侧工具栏承载、底部状态栏、关于/详情对话框、多图模型、打开/导入/导出流程编排 |
| 影像查看器 | `src/components/Viewer.vue` | **右侧竖向工具栏**（窗位/窗宽/帧/缩放/重置/导出）、画布交互、单帧导出 |
| 窗映射算法 | `src/windowing.ts` | HU→灰度映射、MONOCHROME1 反转 |
| 数据模型 | `src/types.ts` | `DicomMeta` / `DicomImage` / `NiftiMeta` / `ImageInfo` / `FileTags` 等接口 |
| 主题变量 | `src/style.css` | 配色 / 前景 / 边框 / 强调色 CSS 变量 |
| 入口 | `src/main.ts`、`index.html` | 挂载 `#app`、页面标题 |

## 2. 整体布局

单窗口**纵向四段式**：顶部菜单栏（固定）、中部主内容区（自适应填满、左侧画布 + 右侧工具栏）、底部状态栏（固定）、可选的批量导出结果横幅（插入菜单栏与主区之间）。

│ 菜单栏 menubar                                                       │
│  ☰ 文件   ☰ 帮助                                                     │
│   ├ 打开文件…                                                         │
│   ├ 从文件夹导入…                                                     │
│   └ 批量导出…                          (帮助 → 关于 → 弹出关于对话框) │
├──────────────────────────────────────────────────────────────────┤
│ （批量导出结果横幅，仅导出后出现）                                      │
├──────────────────────────────┬───────────────────────────────────┤
│ 主内容区 main                  │ 右侧工具栏 sidebar-toolbar         │
│  ├─ 占位态（无图）：            │  ┌ 视图   [重置]                   │
│  │  [打开文件] [载入示例体数据]  │  │  窗位  [===o===]                 │
│  │  支持格式提示                │  │  窗宽  [==o==]                   │

│                                 │  └──────────────                 │

- `menubar`：`display:flex`、底部 1px 边框、背景 `--panel`；菜单项 hover/展开态高亮。
- `main`：`flex:1; min-height:0`，内部 `display:flex` —— 画布区 `flex:1` + 右侧工具栏固定宽。
- `sidebar-toolbar`：竖向排列控件，`width` 固定（约 200px），背景 `--panel`、左侧 1px 边框。
- `canvas`：绘图缓冲随容器尺寸变化（`ResizeObserver` + `devicePixelRatio`），不再写死 800×600；CSS `flex:1; width:100%`，黑底。
- `statusbar`：`display:flex`、顶部 1px 边框、背景 `--panel`、11–12px 灰字。

## 3. 界面状态机

查看器组件 `Viewer` 通过 `:key` 强制重挂载刷新（见 §6）。应用级状态由 `App.vue` 的响应式变量驱动：

| 状态 | 触发条件 | 界面表现 |
|------|----------|----------|
| 初始占位 | `imageList` 为空 | 居中显示"打开文件""载入示例体数据"按钮 + 格式提示 |
| 加载中 | `loading === true` | 菜单项禁用、状态栏/占位区提示"解码中…" |
| 错误 | `error !== null` | 占位态下方红字 `⚠ {error}`（后端错误字符串或前端异常） |
| 正常查看（DICOM/图像/HTJ2K） | `imageList` 中激活项 `view` 有值 | 渲染 `Viewer`（`:key="img-{openSeq}"`） |
| 正常查看（NIfTI MPR） | 激活项 `view` 为 NIfTI 体 | 渲染 `Viewer`（`:key="nii-{openSeq}-{niftiKey}"`）+ MPR 切换栏 |
| 多图列表 | `imageList.length > 1` | 状态栏文件名处出现下拉，列出已导入图像，选中即切换 |
| 示例数据 | `meta.path` 以 `mock` 开头 | 导出按钮禁用，提示"示例数据不可导出" |
| 批量导出完成 | `batchResult` 有值 | 顶部绿色横幅：成功 N 张 / 失败 M 张 + 失败清单 + 关闭 |

### 多图模型（v1.1 新增）
`App.vue` 维护 `imageList: { id, info: ImageInfo, view: ImageView | null }[]` 与 `activeId`。
- **单张"打开文件"**：替换整个列表为单张（独占显示，不进多图下拉）。
- **"从文件夹导入"**：后端 `list_folder_images(dir)` 扫描**文件夹顶层**影像文件返回概要 `ImageInfo[]`（不解码像素）；前端追加到 `imageList`，列表 >1 张时状态栏显示下拉。
- **切换**：选中下拉项 → 若其 `view` 尚未加载，则按扩展名调 `load_*` 懒加载像素；切换 `activeId` → `openSeq` 自增 → `Viewer` 重挂载刷新。
- **重开刷新机制**：每次激活项变化（打开/切换/导入），`openSeq` 自增作为 `Viewer` 的 `:key`。若不加重挂载，Vue 复用同一实例、仅更新 prop，但 `render()` 仅由 `watch` 与 `onMounted` 触发，旧图残留。

## 5. 查看器（Viewer）组件

由 `src/components/Viewer.vue` 实现。接收两个 prop：`meta: DicomMeta`、`frames: Float32Array[]`（每帧 HU 数组，长度 `width*height`）。
布局为「**画布（左，自适应） + 右侧竖向工具栏（sidebar-toolbar）**」，原顶部工具栏与元信息栏已移除（元信息上移至 §6 状态栏）。

### 5.1 右侧工具栏（sidebar-toolbar）

工具栏竖向分为两个分组（`section.group`）：

**「视图」组**（组标题最右侧放置 `重置` / `关闭` 两个迷你按钮）
| 控件 | 绑定 | 范围 | 说明 |
|------|------|------|------|
| **窗位** slider | `wc`（v-model.number） | `huMin` ~ `huMax`，step 1 | 窗中心；变化即触发 `render()` |
| **窗宽** slider | `ww`（v-model.number） | 1 ~ `huMax-huMin`，step 1 | 窗跨度；变化即触发 `render()` |
| **帧** slider | `frameIndex`（仅 `frames>1` 显示） | 0 ~ `frames-1` | 多帧/序列导航，显示 `当前/总数` |
| **重置**（组内标题右侧） | 按钮 | — | 恢复 `zoom=1; pan={0,0}; wc=windowCenter; ww=windowWidth; frameIndex=0` |

**「导出」组**
| 控件 | 绑定 | 范围 | 说明 |
|------|------|------|------|
| 导出格式 `select` | `exportFormat` | `png` / `jpeg` / `htj2k`（HTJ2K 默认 `.jph`） | 选 `jpeg` 时显示质量滑杆 |
| 质量 slider | `exportQuality` | 10–100（仅 jpeg） | JPEG 质量 |
| **导出当前帧** | 按钮 | — | 取当前帧 HU 字节 → 调后端 `export_frame`（按当前 `wc/ww` 窗映射与编码）→ 弹保存框；`mock` 数据禁用 |

> 原「缩放」滑杆已移除，缩放交互改为滚轮 + 拖拽平移（见 §5.2）；当前缩放比例以画布右下角角标 `1.00x` 实时显示（`.zoom-badge`，`pointer-events:none`）。

### 5.2 画布与交互
- 画布绘图缓冲随容器尺寸变化：首次加载 `fitToView()` 等比居中铺满可视区（仅适配一次，之后保留手动缩放）；`ResizeObserver` 监听容器尺寸变化重绘；卸载时 `disconnect()` 清理。
- 高分屏清晰度：缓冲尺寸乘 `devicePixelRatio`，`render()` 中 `dw/dh` 同步乘 `dpr`。
- **滚轮缩放**：`deltaY<0` 放大 1.1×、否则缩小，限制 0.1×–8×（`onWheel`，`.prevent` 阻止页面滚动）。
- **拖拽平移**：`mousedown→mousemove` 更新 `pan`，`mouseup/mouseleave` 结束。
- 渲染流程（`render()`）：取 `frames[frameIndex]` → 窗映射写入复用 `rgba` 缓冲 → 离屏 canvas 原分辨率 `putImageData` → 主 canvas `drawImage` 居中并按 `zoom` 缩放（最近邻 `imageSmoothingEnabled=false`）。
- 空帧/尺寸不匹配（`frame.length===0` 或 `rgba.length!==frame.length*4`）安全跳过或重建缓冲，避免 `ImageData` 尺寸异常抛错导致画布空白。

### 5.3 窗映射（windowing.ts）
`applyWindow(frame, wc, ww, rgba, photometric)`：按窗 `wc/ww` 将 HU 线性映射到 0–255；`MONOCHROME1` 做灰度反转。滑块边界取自 `meta.huMin/huMax`（后端解码已含 Modality LUT 的 HU 区间）；窗值单位为 HU（后端 `decode_dicom_file` 在有 Rescale 时已把 `WindowCenter/Width` 换算到 HU）。

## 8. 标签详情对话框（Tag Detail Dialog，v1.1 新增）

点击状态栏「更多信息」按钮，调后端 `file_tags(path)` 返回该文件的标签信息，模态对话框展示（含搜索框，可按 Tag / 关键字 / 值过滤）。

`file_tags` 按文件类型返回不同内容（`FileTags.kind`）：
- **DICOM**：遍历全部数据元素，每行 `{ tag: "(gggg,eeee)", vr, keyword, value }`，其中 `keyword` 经标准字典 `dicom-dictionary-std` 反查；像素数据元素 `(7FE0,0010)` 的值以「像素数据已省略」占位，避免超大载荷。
- **NIfTI**：返回体数据头字段（尺寸、数据类型、体素大小、斜率/截距等）。
- **图像 / HTJ2K**：尽力读取格式头（尺寸、色彩类型、位深、文件大小等）；HTJ2K 复用解码路径得到基础信息。

对话框为可滚动表格，列：Tag（/索引）、VR、关键字、值、操作；顶部搜索框实时过滤行。

### 8.1 标签行单行显示与展开（v1.2 新增）
- **默认单行**：值列（`.tags-table td.val`）使用 `white-space:nowrap; overflow:hidden; text-overflow:ellipsis; max-width:240px`，整行只显示一行，过长值以省略号截断。
- **溢出检测**：通过 `valRefs`（值单元格 `:ref`）在 `filteredTags` 变化后 `nextTick` 中 `measureOverflow()` 比较 `scrollWidth > clientWidth`，得到 `overflowMap` 标记哪些行溢出。
- **展开/收起按钮**：当且仅当某行溢出（`overflowMap[tag]`）或已展开（`expandedTags.has(tag)`）时，行尾「操作」列显示「展开」（点击后该值列加 `.expanded` 类，`white-space:normal; word-break:break-all`，可换行完整查看）/"收起"切换按钮，点击 `toggleTag(tag)` 在 `expandedTags` 集合中增删。
- **操作列钉住（v1.3 新增）**：操作列（`.tags-table th:last-child, td:last-child`）设 `position:sticky; right:0; background:var(--panel); border-left:1px solid var(--border)`，对话框宽度不足、表格出现横向滚动时，「展开/收起」按钮始终钉在右侧可见区，不会因值列溢出而被挤出可视范围。
- 搜索过滤、切换图像重新打开对话框时均重置 `expandedTags` 与 `detailsQuery`，并重新测量溢出。

## 9. MPR 多平面重建视图（NIfTI）

NIfTI 体数据走独立渲染分支（`niftiRender` computed）：将 `[x][y][z]` 体按轴重排为多帧 `frames` 后复用 `Viewer`。

- **MPR 切换栏**（`.mpr-bar`，仅 NIfTI 激活时显示）：轴向 / 冠状 / 矢状 三按钮（`active` 高亮当前轴）、右侧显示体尺寸 `nx × ny × nz`。
- 切换轴 → `niftiView.axis` 变化 → `niftiKey` 变化 → `Viewer` `:key` 变化 → 重挂载并重排帧。
- NIfTI 的 `meta` 由 `extractNifti()` 结果 + `huMin/huMax` 构造（`windowCenter=(huMin+huMax)/2`、`windowWidth=huMax-huMin`）。

## 10. 批量导出流程

1. 点「文件 → 批量导出…」 → 弹出**多选**文件框（同 §4 过滤器）。
2. 选中后弹出**目录**选择框（"选择批量导出目录"）。
3. 调后端 `batch_export({paths, format, quality, outDir})`，`batchBusy` 期间菜单项禁用、文案"导出中…"。
4. 返回 `BatchResult{ok, failed[]}` → 菜单栏下方绿色横幅展示成功数、失败数（含失败清单 `path—error`）与"关闭"按钮。

## 11. 视觉规范（Theme Tokens）

来自 `src/style.css` 的 `:root` CSS 变量，深色主题：

| Token | 值 | 用途 |
|-------|-----|------|
| `--bg` | `#0d1117` | 页面/画布外背景 |
| `--panel` | `#161b22` | 菜单栏、右侧工具栏、状态栏、导出区背景 |
| `--border` | `#30363d` | 分隔线/边框 |
| `--fg` | `#e6edf3` | 主文字/文件名 |
| `--fg-dim` | `#8b949e` | 副标题/标签/提示/元信息 |
| `--accent` | `#2f81f7` | 主操作按钮、激活态、导出按钮、滑块 accent |

通用排版：
- 字体：`-apple-system, "Segoe UI", "Microsoft YaHei", sans-serif`。
- 按钮：透明底 + `--border` 描边、圆角 6px、12–13px；主操作为 `--accent` 实底白字。
- 滑块控件：12px 标签 + 滑杆 + 固定最小宽数值（窗位 44px、质量 28px 右对齐）。
- 画布：黑底（`#000`），强调灰度影像对比。
- 对话框：遮罩 + 居中卡片（`--panel` 背景、--border 边框），关于/详情共用模态样式。

状态色（横幅/提示）：
- 成功：`#2e9e5b`（导出成功文案）
- 失败/错误：`#e5484d`（导出失败、错误提示）
- 批量横幅底：`#16331f`、文字 `#c8f0d4`、失败清单 `#e5a3a3`

## 12. 交互与导航流程

```
[文件→打开文件] ──选择──▶ 解码(loading) ──成功(替换列表)──▶ Viewer(查看/调窗/导出)
                         │                                    │
                         └──失败──▶ 占位态红字错误
[文件→从文件夹导入] ──选目录──▶ list_folder_images(顶层扫描) ──追加列表──▶ 状态栏多图下拉
[状态栏下拉] ──选文件──▶ (未加载则懒加载 load_*) ──切换 activeId──▶ openSeq++ ──▶ Viewer 重挂载
[文件→批量导出] ──多选+选目录──▶ batch_export(导出中) ──▶ 结果横幅
[右侧工具栏→导出当前帧] ──▶ export_frame(按当前窗) ──▶ 保存框
[状态栏→更多信息] ──▶ file_tags ──▶ 标签详情对话框(单行/可展开/可搜索)
[帮助→关于] ──▶ 关于对话框(图标/名称/版本/作者/邮箱)
[关闭] ──▶ clearView ──▶ 占位态
```

- 单文件查看与批量导出共用文件菜单入口，互不影响。
- 任意时刻只有一个查看器（DICOM/图像/HTJ2K 走激活项 `view`，NIfTI 走 `niftiRender`）。
- 多图下拉仅在从文件夹导入 ≥2 张时出现；单张"打开文件"独占显示。

## 13. 已知限制与后续演进

- **仅未压缩 DICOM**：压缩传输语法（JPEG2000 等）暂未支持，打开会走后端错误提示。
- **批量导出为"每文件默认窗"**：尚无序列分组（SeriesInstanceUID）面板与逐文件窗预览。
- **窗映射在 CPU（前端 JS）**：超大幅面（4K×4K）有性能压力，后续可下放 Rust/WASM 或 GPU。
- **示例数据（mock）**仅用于前端联调，不可导出。
- **"从文件夹导入"仅扫描顶层**：递归子目录尚未支持（如需请说明）。
- 自适应/可访问性：当前为固定桌面布局，未做移动端适配与键盘可达性（滑块已可键盘操作，但画布缩放/平移依赖鼠标）。

## 附录 A：关键数据模型（`src/types.ts`）

```ts
interface DicomMeta {
  path: string; filename: string;
  width: number; height: number; frames: number;
  bitsStored: number;
  pixelRepresentation: number; // 0=unsigned, 1=signed
  slope: number; intercept: number;
  windowCenter: number; windowWidth: number;
  photometric: string;          // MONOCHROME1/2, RGB…
  huMin: number; huMax: number; // 滑块边界，已含 Modality LUT
}
interface DicomImage { meta: DicomMeta; pixelBytes: Uint8Array | string | number[]; }
interface NiftiMeta  { path: string; filename: string; dims: [number,number,number]; huMin: number; huMax: number; }
interface NiftiVolume { meta: NiftiMeta; voxelBytes: Uint8Array | string | number[]; }

// v1.1 新增：已导入图像概要（多图下拉 / 状态栏用，不携带像素）
interface ImageInfo {
  path: string; filename: string;
  kind: string;          // "dicom" | "image" | "nifti" | "htj2k"
  width: number; height: number; frames: number;
  bitsStored: number; photometric: string;
  note?: string;         // 可选提示（如"示例数据"）
}

// v1.1 新增：标签详情（file_tags 返回值）
interface TagRow { tag: string; vr: string; keyword: string; value: string; }
interface FileTags {
  kind: string;          // "dicom" | "nifti" | "image"
  filename: string;
  rows: TagRow[];
}

interface BatchResult { ok: number; failed: { path: string; error: string }[]; }
```

> `pixelBytes`/`voxelBytes` 经 Tauri v2 JSON IPC 时为 `number[]`（serde_bytes 退化），前端 `decodePixelBytes` 统一兼容 `number[] / Uint8Array / base64 string` 三种形态。

## 附录 B：新增后端命令（v1.1）

| 命令 | 入参 | 返回 | 用途 |
|------|------|------|------|
| `file_tags` | `{ path }` | `FileTags` | 读取文件标签：DICOM 全量标签（keyword 经标准字典反查）、NIfTI 头字段、图像/HTJ2K 格式头；供状态栏「更多信息」按钮使用 |
