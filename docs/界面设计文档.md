## 1. 概述

### 1.1 产品定位
医学影像处理软件是一款**轻量、可本地离线运行**的桌面医学影像查看与处理工具，覆盖 DICOM / 常规图像 / NIfTI 体数据 / HTJ2K 的导入、窗位调校、格式转换与 JPEG 导出闭环。前端为 Tauri 内嵌 WebView（Vue 3 + TypeScript + Vite）。

### 1.2 设计目标
- **零学习成本**：单窗口、单主操作（"打开文件"），核心交互即"选图→调窗→导出"。
- **影像优先**：画布占据主区域，菜单/工具/状态为窄条、不挤占阅片空间。
- **实时反馈**：窗位、窗宽、缩放、帧切换均实时重绘，无确认步骤。
- **深色优先**：医学阅片以暗背景减少眩光、突出灰度影像。

### 1.3 本版界面范围
| 模块 | 文件 | 说明 |
|------|------|------|
| 应用外壳 / 布局 / 状态 | `src/App.vue` | 顶部菜单栏、主区占位、右侧工具栏承载、底部状态栏、关于/详情对话框、多图模型、打开/导入/导出流程编排 |
| 影像查看器 | `src/components/Viewer.vue` | 画布交互、导出 JPEG（当前帧 / 整个序列）；**画布右侧帧滚动条**（多帧时竖向列出帧号、点击切换，位于画布与工具栏之间、非工具栏内）；**右侧竖向工具栏**（窗位/窗宽/帧/缩放/重置/导出） |
| 窗映射算法 | `src/windowing.ts` | HU→灰度映射、MONOCHROME1 反转 |
| 数据模型 | `src/types.ts` | `DicomMeta` / `DicomImage` / `NiftiMeta` / `ImageInfo` / `FileTags` 等接口 |
| 主题变量 | `src/style.css` | 配色 / 前景 / 边框 / 强调色 CSS 变量 |
| 入口 | `src/main.ts`、`index.html` | 挂载 `#app`、页面标题 |

### 5.1.1 导出 JPEG 对话框（v1.10）

点击「导出JPEG」弹出模态对话框，由 `Viewer.vue` 调后端 `export_jpeg`（见附录 B）。导出内容按当前 `wc/ww` 窗映射（MONOCHROME1 反转），并叠加四角标签与水印：

- **范围**
  - `当前帧`：仅导出当前显示的切片（取 `frameIndex`）。
  - `整个序列（多帧/多切片）`：将当前序列的全部图像作为**统一序列**导出——多帧（单文件内多帧）、多切片（同系列多文件，按 `series_sort_key` 排序）、NIfTI 体积（按 z 轴拆分）均视为同一序列的连续切片，按统一序号顺序写出，与画布滚动条第 1 张到最后一张一一对应。
- **标签叠加**：勾选常用 DICOM 标签（机构名称、患者编号、序列描述、窗位/窗宽等），渲染到图像四角（每角可叠多项：左上 / 右上 / 左下 / 右下），随当前窗实时取值。
- **水印**：可选文本，渲染到图像中央偏下。
- **质量**：JPEG 质量滑杆 10–100。
- **输出**：`当前帧`→系统保存框选单个 `.jpg`；`整个序列`→系统目录框选文件夹，依次写出 `slice_001.jpg … slice_NNN.jpg`（统一前缀，消除原 `frame`/`slice` 分叉），每张均套用当前窗映射 + 四角标签 + 水印。

### 5.1.2 导出 DICOM 对话框（v1.11）

点击「导出DICOM」弹出模态对话框，由 `Viewer.vue` 调后端 `export_dicom`（见附录 B）。与导出 JPEG 不同，**本功能保留原始像素数据**（不重新编码 HU，CT 的 `RescaleSlope/Intercept` 一并保留，读取端可还原 HU），仅在前端选择的范围内做传输语法转换与可选元数据脱敏，并写入软件标识。

- **范围**
  - `当前帧`：仅导出当前显示的切片（取 `frameIndex`），输出单个 `.dcm` 文件。
  - `整个序列（多帧/多切片）`：导出当前序列的全部图像；源可为多帧（单文件内多帧）、多切片（同系列多文件，按 `series_sort_key` 排序）。
- **压缩方式（传输语法）**
  - `未压缩（显式 VR）` / `未压缩（隐式 VR）`：原始像素原样封装（`PixelData` 为 `OB`/`OW` Primitive）。
  - `RLE 无损`：逐扫描行 PackBits 风格编码（`1.2.840.10008.1.2.5`）。
  - `HTJ2K 无损` / `HTJ2K 有损`：复用 openjph-core（`1.2.840.10008.1.2.4.200` / `.201`，为用户指定 UID；官方 DICOM 注册表为 `.201` / `.202`，如需严格对齐官方注册表改这两行即可）；按 `BitsAllocated` 与像素符号自动适配 8/16-bit、有/无符号。选择 `HTJ2K 有损` 时显示「有损程度」滑杆（openjph-core 0.1.0 无公开 rate/quality API，内部映射到 DWT 分解层数 1–6）。
  - `JPEG-LS 无损`：直接压缩**原始存储像素**（不套窗宽窗位、保留 16-bit 有符号 HU 等原始位深与符号性），采用 **`pure_jpegls` 纯 Rust 编码器**输出 ITU-T T.87 标准 JPEG-LS 流（SOF55），传输语法 `1.2.840.10008.1.2.4.80`（JPEG-LS Lossless，NEAR=0）；显式指定 `precision = BitsAllocated`，确保 8/16-bit、有/无符号像素按相同位深还原。相比旧 `JPEG 8bit 窗映射` 方案，JPEG-LS 无损**不丢诊断位深**、不重写 `BitsAllocated/PixelRepresentation/Rescale` 等标签。
  - `JPEG-LS 有损（近无损）`：同上的 `pure_jpegls` 编码器，但设 `NEAR>0`（DCIOM 传输语法 `1.2.840.10008.1.2.4.81`，JPEG-LS Near-Lossless），最大重建误差 ±NEAR。选择 `JPEG-LS 有损` 时显示「有损程度」滑杆（值即 NEAR，范围 1–100，受 `min(255, MAXVAL/2)` 约束），**不改变像素位深**（仍为原始 8/16-bit）。
- **脱敏**（按分组独立选择方式，默认均为「保留」）
  - 分组：`患者` / `机构` / `人员` / `设备` / `日期时间` / `实例 UID`（分组 id 与后端 `ANON_GROUPS` 对齐；「注释私有」分组已移除）。
  - 方式：`保留` / `删除` / `MD5 摘要` / `加密`；`实例 UID` 组另支持 `重生成 UID`。
  - `加密`：用 `PBKDF2-HMAC-SHA256(密码, 盐)` 派生 256-bit 密钥，AES-256-GCM 加密标签值；**盐与算法标识写入私有标签** `(0099,0010)` Creator="UNIXEL"、`(0099,1001)` 算法标识、`(0099,1002)` 盐、`(0099,1003)` 加密映射（JSON，`OB`）；**密码不写入文件**。**密码为可选项，留空时默认口令 `unixel`**。选择任一分组「加密」时显示密码输入框（占位提示「留空则默认 unixel」）。
  - `重生成 UID`：重新生成 `Study/Series/SOP Instance UID`，脱敏后同步更新 `MediaStorageSOPInstanceUID`。
- **输出形式**（仅 `范围=整个序列` 出现）
  - `单个文件（多帧）`：合并为单文件多帧 Secondary Capture（`SOPClassUID=1.2.840.10008.5.1.4.1.1.7.4`），输出单个 `.dcm`。
  - `多个文件（单帧）`：逐帧写出独立 `.dcm`（`frame_001.dcm … frame_NNN.dcm`），输出到所选文件夹。
- **软件标识（自动）**：导出由后端自动写入 `SoftwareVersions (0018,1020) = "Unixel - Hongwei Shao"`，不修改其它临床标签；对话框不再展示该说明行。
- **输出**：`当前帧` / `整序列单文件` → 系统保存框选单个 `.dcm`；`每帧单文件` → 系统目录框选文件夹。结果以提示「已导出 N 个 DICOM 文件」或错误。

> 说明：导出 DICOM 仅接受 `.dcm` / `.dicom` 源文件；未压缩/有损重编码在源像素基础上进行，不套 Modality LUT（即保留存储的原始值），确保 CT 等模态的 HU 在读取端可经 `Rescale` 还原。

### 5.1.3 导出 NIfTI 对话框（v1.16）

点击「导出NIfTI」弹出模态对话框，由 `Viewer.vue` 调后端 `export_nifti`（见附录 B）。**本功能把 DICOM 序列（或多帧）的 HU 像素导出为 NIfTI 体数据（3D 体或 2D 切片）**，供 MPR / 三维后处理使用。导出数据来自 `load_source_frames` 返回的浮点 HU（已按 inferior→superior 解剖位置重排），经量化后写入指定数据类型；空间信息由 `ImageOrientationPatient`（IOP）/ `ImagePositionPatient`（IPP）/ `PixelSpacing` / `SliceThickness` 推导并写入 `sform`。

- **范围**
  - `当前帧（2D）`：仅导出当前显示的切片，输出单张 2D 图像（`dim[0]=2`）。
  - `整个序列（3D 体）`：导出当前序列全部图像拼成 3D 体（`dim[0]=3`，`dim[4]=切片数`）；源为多切片（同系列多文件，按法向投影排序）或多帧（单文件内多帧）时自动合并。
- **数据类型**（默认 `int16`，前端下拉可选；选择有损/越界时对话框内给出精度提示）
  - `int16`（默认）：HU 整数直存（`scl_slope=1, scl_inter=0`，无损当 HU∈[-32768, 32767]）；越界将被截断（后端在结果中提示）。
  - `int32`：HU 整数直存，范围大，基本无截断风险，但体积极大。
  - `uint16`：先 `+1024` 偏移再存，适用 HU∈[-1024, 64511]；越界截断（后端提示）。
  - `uint8`：**强制有损**，HU 线性映射到 0–255 并裁剪，仅适合预览。
  - `float32` / `float64`：HU 浮点直存，无损保留，但体积大于整数类型（float64 最大）。
  - 量化逻辑：整数类型按类型 `clamp` 到可表示范围；`uint8` 在 `[hu_min, hu_max]` 上线性映射（非固定窗），保证对比度充分利用。
- **朝向**
  - `写入 sform（RAS 仿射）`（默认勾选）：由 IOP 求切片法向 `n`，结合首切片 `IPP` 原点与像素间距构造 RAS 仿射 `srow_{x,y,z}`（DICOM 为 LPS，NIfTI 标准用 RAS，故对 x、y 分量取负）；`sform_code=1`、`xyzt_units` 设空间单位为 mm。取消勾选则仅写像素间距 `pixdim`（无空间朝向）。
- **压缩**
  - `输出 .nii.gz（gzip 压缩）`（默认勾选）：写入 gzip 压缩的 `.nii.gz`；取消则写未压缩 `.nii`。后端按选项自动补扩展名（`ensure_nii_ext`）。
- **软件标识（自动）**：导出由后端自动写入 `descrip` 字段 `Unixel - Hongwei Shao`。
- **输出**：系统保存框选单个 `.nii` / `.nii.gz` 文件（依据压缩选项由后端补扩展名）。结果以提示「已导出 NIfTI：…」或错误（含精度损失说明，如整数类型越界截断）。

> 说明：导出 NIfTI 仅接受 `.dcm` / `.dicom` / `.nii` / `.nii.gz` 源（走 `load_source_frames`，与查看器同源）；整体系列可来源于多切片（同系列多文件，按法向投影排序取首切片原点）或多帧单文件。量化在 HU 浮点域完成，整数类型按类型范围 clamp，确保 CT 的 HU 在 NIfTI 读取端可直接还原（int16 默认策略下 `scl=1` 即标准无损存 HU）。

### 5.2 画布与交互
- 画布绘图缓冲随容器尺寸变化：首次加载 `fitToView()` 等比居中铺满可视区（仅适配一次，之后保留手动缩放）；`ResizeObserver` 监听容器尺寸变化重绘；卸载时 `disconnect()` 清理。
- 高分屏清晰度：缓冲尺寸乘 `devicePixelRatio`，`render()` 中 `dw/dh` 同步乘 `dpr`。
- **滚轮缩放**：`deltaY<0` 放大 1.1×、否则缩小，限制 0.1×–8×（`onWheel`，`.prevent` 阻止页面滚动）。
- **拖拽平移**：`mousedown→mousemove` 更新 `pan`，`mouseup/mouseleave` 结束。
- 渲染流程（`render()`）：取 `frames[frameIndex]` → 窗映射写入复用 `rgba` 缓冲 → 离屏 canvas 原分辨率 `putImageData` → 主 canvas `drawImage` 居中并按 `zoom` 缩放（最近邻 `imageSmoothingEnabled=false`）。
- 空帧/尺寸不匹配（`frame.length===0` 或 `rgba.length!==frame.length*4`）安全跳过或重建缓冲，避免 `ImageData` 尺寸异常抛错导致画布空白。

### 5.3 窗映射（windowing.ts）
`applyWindow(frame, wc, ww, rgba, photometric)`：按窗 `wc/ww` 将 HU 线性映射到 0–255；`MONOCHROME1` 做灰度反转。滑块边界取自 `meta.huMin/huMax`（后端解码已含 Modality LUT 的 HU 区间）；窗值单位为 HU（后端 `decode_dicom_file` 在有 Rescale 时已把 `WindowCenter/Width` 换算到 HU）。

## 8. 标签详情对话框（Tag Detail Dialog，v1.1 新增）

点击状态栏「更多信息」按钮，调后端 `file_tags(path)` 返回该文件的标签信息，模态对话框展示（含搜索框，可按 Tag / 关键字 / 值过滤）。

`file_tags` 按文件类型返回不同内容（`FileTags.kind`）：
- **DICOM**：遍历全部数据元素，每行 `{ tag: "(gggg,eeee)", vr, keyword, value, description }`，其中 `keyword` 经标准字典 `dicom-dictionary-std` 反查，`description` 为**标签含义解释 + 常见取值**（后端 `tag_explanation(keyword)` 释义表；`dicom-dictionary-std` 标准字典无标签名 name 字段，未收录的关键字回退为 `VR xx（VR 中文含义）`）；像素数据元素 `(7FE0,0010)` 的值以「像素数据已省略」占位，避免超大载荷。
- **NIfTI**：返回体数据头字段（尺寸、数据类型、体素大小、斜率/截距等）。
- **图像 / HTJ2K**：尽力读取格式头（尺寸、色彩类型、位深、文件大小等）；HTJ2K 复用解码路径得到基础信息。

对话框为可滚动表格，列：Tag（/索引）、VR、关键字、值、操作；顶部搜索框实时过滤行。

### 8.1 标签行单行显示与展开（v1.2 新增）
- **默认单行**：值列（`.tags-table td.val`）使用 `white-space:nowrap; overflow:hidden; text-overflow:ellipsis; max-width:240px`，整行只显示一行，过长值以省略号截断。
- **溢出检测**：通过 `valRefs`（值单元格 `:ref`）在 `filteredTags` 变化后 `nextTick` 中 `measureOverflow()` 比较 `scrollWidth > clientWidth`，得到 `overflowMap` 标记哪些行溢出。
- **展开/收起按钮**：当且仅当某行溢出（`overflowMap[tag]`）或已展开（`expandedTags.has(tag)`）时，行尾「操作」列显示「展开」（点击后该值列加 `.expanded` 类，`white-space:normal; word-break:break-all`，可换行完整查看）/"收起"切换按钮，点击 `toggleTag(tag)` 在 `expandedTags` 集合中增删。
- **操作列钉住（v1.3 新增）**：操作列（`.tags-table th:last-child, td:last-child`）设 `position:sticky; right:0; background:var(--panel); border-left:1px solid var(--border)`，对话框宽度不足、表格出现横向滚动时，「展开/收起」按钮始终钉在右侧可见区，不会因值列溢出而被挤出可视范围。
- 搜索过滤、切换图像重新打开对话框时均重置 `expandedTags` 与 `detailsQuery`，并重新测量溢出。

### 8.2 标签说明「?」、关闭「×」与导出（v1.5 新增）

**关键字说明「?」图标**
- 每行「关键字」单元格后紧跟一个圆形「?」图标（`.qmark`，`border-radius:50%` 描边小圆 + 居中问号）；仅当 `row.description` 非空时渲染（`v-if="r.description"`）。
- **仅 DICOM 显示**：`file_tags` 仅对 DICOM 行填充 `description`（含义解释 + 常见取值），NIfTI / 图像 / HTJ2K 行的 `description` 为空字符串，前端故不渲染问号。
- **hover 说明（v1.7 升级）**：鼠标悬停「?」时弹出 `.qtip` 浮层，含三段——关键字（`.qtip-key`）、说明（`.qtip-desc`，即 `description`，现为该标签的**含义解释与常见取值**，便于快速理解字段语义）、当前值（`.qtip-val`，即 `value`）；纯 CSS `:hover` 显隐，无需 JS。

**关闭「×」**
- 原对话框底部的「关闭」文字按钮移除，现由标题栏右侧内联「×」关闭按钮（`.modal-close-x`，与导出对话框 `.modal-close` 同款：hover 浅底高亮）承担关闭（置 `detailsOpen=false`）；标题栏底色 `var(--bg-2, #1c1f26)`（比内容区 `--panel` 略深一档），与 §5.1.1–§5.1.3 导出对话框风格统一。

**导出（v1.7 调整）**
- 对话框头部仅保留「导出」按钮（移除原格式 `select`）：点击 → `save()` 系统保存框，过滤器为 `JSON(*.json)` 与 `CSV(*.csv)` 两个选项，用户在系统框的「文件类型」下拉中选择格式 → 调后端 `export_tags({ path, format, rows })`（按所选扩展名推断 `format`（`*.csv`→csv，其余→json），传完整 `rows`）→ 写入用户指定路径。
- 导出中 `exportingTags` 禁用按钮并显示 `导出中…`，结果以 `.export-tags-msg` 提示「已导出：{path}」或错误。
- `csv` 由后端 `tags_to_csv` 生成（字段 `tag,vr,keyword,value,description`，含双引号/逗号/换行转义）；`json` 由 `serde_json::to_string_pretty` 生成。

## 12. 交互与导航流程

```
[文件→打开文件] ──选择──▶ 解码(loading) ──成功(替换列表)──▶ Viewer(查看/调窗/导出)
                         │                                    │
                         └──失败──▶ 占位态红字错误
[文件/占位态→从文件夹导入] ──选目录──▶ scan_folder_series(递归扫描+Study/Series 两级分组)
        │
        ├─ 仅 1 个 Series ──▶ load_series_files(仅该序列) ──替换列表──▶ Viewer + 状态栏按系列分组下拉
        └─ 多个 Series ──▶ 序列选择对话框(按 Study 分组,行内显示序列日期/患者姓名)
                                │ 选定
                                └─▶ load_series_files(仅所选序列) ──替换列表──▶ Viewer
[状态栏下拉(optgroup)] ──选文件──▶ (未加载则懒加载 load_*) ──切换 activeId──▶ openSeq++ ──▶ Viewer 重挂载
[查看态多帧→画布右侧帧滚动条] ──点击帧号──▶ frameIndex=帧号 ──▶ 重绘
[右侧工具栏→导出JPEG] ──▶ 导出JPEG对话框(范围/标签/水印/质量) ──▶ export_jpeg(按当前窗) ──▶ 当前帧→保存框 / 整个序列→slice_001…NNN.jpg
[右侧工具栏→导出DICOM] ──▶ 导出DICOM对话框(范围/传输语法/脱敏分组与方式/整序列输出) ──▶ export_dicom(保留原始像素+可选脱敏+写标识) ──▶ 当前帧/整序列单文件→保存框.dcm / 每帧单文件→frame_001…NNN.dcm
```

- 多图下拉仅在从文件夹导入 ≥2 张时出现；单张"打开文件"独占显示。

## 13. 已知限制与后续演进

- **导入仅未压缩 DICOM**：读取端暂不支持压缩传输语法（JPEG2000/JPEG-LS/HTJ2K 等）源文件，打开会走后端错误提示；但**导出**已支持未压缩 / RLE / HTJ2K（无损·有损）/ JPEG（8bit 窗映射）多种传输语法（见 §5.1.2）。
- **窗映射在 CPU（前端 JS）**：超大幅面（4K×4K）有性能压力，后续可下放 Rust/WASM 或 GPU。
- **示例数据（mock）**仅用于前端联调，不可导出。
- **"从文件夹导入"已支持递归子目录**（v1.7）：按 `StudyInstanceUID → SeriesInstanceUID` 两级聚合；非 DICOM（PNG/JPG/TIFF/HTJ2K）归入「其他影像文件」分组；NIfTI 仍走「打开文件」单文件入口，文件夹导入暂不包含 NIfTI。
- 自适应/可访问性：当前为固定桌面布局，未做移动端适配与键盘可达性（滑块已可键盘操作，但画布缩放/平移依赖鼠标）。

| `export_dicom`（v1.11） | `{ mode, filePath, seriesPaths, frameIndex, transferSyntax, quality, wc, ww, anonRanges:[{id,method}], password, output, multifile }` | `String`（"已导出 N 个 DICOM 文件"） | DICOM 导出（保留原始像素）：`transferSyntax` ∈ `implicit`/`explicit`/`rle`/`htj2k_lossless`/`htj2k_lossy`/`jpeg`；`mode="current"` 取单帧单文件，`mode="all"` 时 `multifile=true` 逐帧写出 `frame_NNN.dcm`、否则合并多帧单个 `.dcm`（Secondary Capture，`SOPClassUID=1.2.840.10008.5.1.4.1.1.7.4`）。`anonRanges` 为脱敏分组方式列表（id∈`patient/institution/personnel/device/datetime/comment/uid`，method∈`keep/delete/hash/encrypt/regenerate`）；`encrypt` 用 PBKDF2-HMAC-SHA256+AES-256-GCM、盐与映射存私有标签 `(0099,xxxx)`（Creator="UNIXEL"），`password` 不入库；导出统一写入 `SoftwareVersions="Unixel - Hongwei Shao"`。多切片系列整序列经 `seriesPaths` 逐文件加载，多帧单文件无需 `seriesPaths` |

> 像素数据元素在 `file_tags` 中以「像素数据已省略」占位，避免超大载荷拖垮前端渲染。
> 系列分组排序（`group_and_sort_series`）：按 `series_uid` 分组；组内排序键 `series_sort_key` 优先级为 **① `ImagePositionPatient` 沿法向量投影**（法向量 = `cross3(IOP[0..3], IOP[3..6])` 归一化）→ ② `InstanceNumber` → ③ `SliceLocation` → ④ 0.0；组间按 `(seriesNumber, modality, filename)` 排序（`None` 系列置末）。结果写入 `series_group`（同系列相同编号）/ `series_label`。
